## 1. 概述

### 1.1 背景

当前 `infra-yamlops` 的 `internal/interfaces/cli/` 包混合了两种完全不同的交互模式：

- **Cobra CLI 命令**：面向自动化工具执行（`plan`、`apply`、`validate` 等）
- **BubbleTea TUI**：面向人类在终端中的交互式操作（菜单导航、树形选择、实时状态等）

这两类代码共存于同一个 Go package 中，导致：
- 职责边界模糊
- 第三方依赖混乱（CLI 不需要 `bubbletea`、`lipgloss`）
- 未来无法独立演进（如添加 HTTP API 接口层）

### 1.2 目标

将 `interfaces/cli` 拆分为两个独立包：

- `interfaces/cli/` — 纯 Cobra 命令（自动化工具执行）
- `interfaces/tui/` — BubbleTea TUI（人类交互终端）

调用方式变为：

```bash
yamlops tui                        # 启动交互式 TUI
yamlops cli plan                   # CLI 执行 plan
yamlops cli apply                  # CLI 执行 apply
yamlops cli app plan               # CLI 子命令嵌套
yamlops cli service deploy         # CLI 服务操作
yamlops api                        # 未来 HTTP API（预留）
```

### 1.3 范围

- 仅涉及 `internal/interfaces/` 层的文件拆分
- 不改动 `application/`、`domain/`、`infrastructure/` 层
- 不改动业务逻辑

## 3. 术语定义

| 术语 | 说明 |
|------|------|
| CLI | Command Line Interface，基于 Cobra 的非交互式命令行 |
| TUI | Terminal User Interface，基于 BubbleTea 的交互式终端界面 |
| Cobra | Go 的 CLI 框架 |
| BubbleTea | Charmbracelet 的终端 TUI 框架 |
| Lipgloss | Charmbracelet 的终端样式库 |
| 接口层 | `internal/interfaces/` 目录，负责外部交互 |

## 6. 开发注意事项

### 6.1 `package` 声明

所有迁移到 `interfaces/tui/` 的文件：
```go
// Before
package cli

// After
package tui
```

### 6.2 文件名去前缀

TUI 文件在新包内不需要 `tui_` 前缀（已在 `tui/` 包下），但保留语义化命名。

### 6.3 TUI 独立性验证

TUI 文件直接调用以下包，**不依赖 `interfaces/cli`**：

- `tui/tree.go` → `persistence.NewConfigLoader`、`orchestrator.NewStateFetcher`、`plan.NewPlanner`、`usecase.NewExecutor`
- `tui/dns_actions.go` → `infradns.NewFactory`
- `tui/service_common.go` → `ssh.NewClientWithConfig`
- `tui/cleanup.go` → `ssh.NewClientWithConfig`
- `tui/server.go` → `serverpkg.NewChecker`、`serverpkg.NewSyncer`

### 6.4 `tui/cursor.go` 的 `init()` 函数

`cursor.go:96-204` 注册了所有 `CursorController`，依赖 `ViewState` 常量和 `Model` 类型。这些都在 `tui/model.go` 中定义，迁移后在同一包内，无需改动。

### 6.5 `tui/render.go` 与 `tui/menu.go` 的交叉引用

`render.go` 调用 `formatNodeStatus()`（定义在 `menu.go`）。同一包内，迁移后自然可用。

### 6.6 `cmd/yamlops/main.go` 更新

```go
package main

import (
    "log/slog"
    "os"

    "github.com/lite-lake/infra-yamlops/internal/infrastructure/logger"
    "github.com/lite-lake/infra-yamlops/internal/interfaces/cli"
)

func main() {
    logLevel := slog.LevelInfo
    if os.Getenv("YAMLOPS_DEBUG") != "" {
        logLevel = slog.LevelDebug
    }
    logFormat := os.Getenv("YAMLOPS_LOG_FORMAT")

    logger.Init(&logger.Config{
        Level:     logLevel,
        Format:    logFormat,
        AddSource: os.Getenv("YAMLOPS_DEBUG") != "",
    })

    cli.Execute()
}
```

`main.go` 本身不需要改动，因为 `cli.Execute()` 内部会 import `tui.Run()`。

### 6.7 `root.go` 重构要点

**原结构**（当前）：

## 11. 风险评估

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| `tui/cursor.go` 的 `init()` 注册失败 | 低 | TUI 无法启动 | `ViewState` 常量在同一包内，迁移后自然可用 |
| TUI 内部函数交叉引用断裂 | 低 | 编译失败 | 所有 TUI 文件在同一包内，函数引用自然可用 |
| CLI 子命令注册遗漏 | 中 | 部分命令不可用 | 逐一对照原 `root.go` 的 `AddCommand` 列表 |
| 测试文件 import 路径错误 | 中 | 测试失败 | 更新所有测试文件的 import 路径 |
| `cmd/yamlops/main.go` import 缺失 | 低 | 编译失败 | `main.go` 只 import `cli`，由 `cli` import `tui` |
